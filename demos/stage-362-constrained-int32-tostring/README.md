# Stage 362 · Constrained Int32 ToString

A `constrained. int32 callvirt Object::ToString` call now links to the original CoreLib `Int32.ToString()` override on the live receiver address, without boxing. The boxed form, `box int32` and then `callvirt Object::ToString`, already selected that override, so both forms now reach the same body. Constrained Int32 `Equals(object)` keeps its direct scalar binding. Constrained Int32 `GetHashCode`, and a constrained authored value override that mutates its parameter copy, keep their existing behavior.

The fixture compiles one ordinary C# library and compares it with Windows x86 CLR 10.0.10 in Node and Edge. Run it once with the browser Mono CoreLib metadata and once with the x86 CoreCLR metadata. Three cases execute and match the CLR. The seven Int32 ToString cases now pass dispatch and stop at a shared located dependency in both profiles. That stop is `Number.NegativeInt32ToDecStr`, which writes digits through a pinned `char&` into a fresh `FastAllocateString` result. It is Mono MethodDef 6220 IL_002B and CoreCLR MethodDef 6932 IL_002C. The oracle finds that row and offset in whichever CoreLib it links. With the Stage 360 compiler, the constrained cases were rejected at the `Format<T>` constrained prefix, and the boxed cases already stopped at the formatting body. A value type that inherits `Object.ToString` still needs a boxed receiver and keeps its diagnostic at the constrained prefix.

Number formatting into a fresh string is a separate dependency. It needs the culture `NegativeSign` from `NumberFormatInfo.CurrentInfo` and digit writes into the new string's characters, and Wasm GC strings cannot be addressed through linear memory. Until both exist, the compiler keeps the explicit diagnostic and does not substitute an invariant formatter.

When the stock .NET 10 `blazorwasm` template publish is packed exactly as in Stage 112, it moves from `-2 [2,8671,234]` to `-1 [5,17,26]`. The first is CoreLib `DefaultInterpolatedStringHandler.AppendFormatted<T>` IL_00EA. The second is `ComponentParametersTypeCache.GetParameterType` IL_001A in Microsoft.AspNetCore.Components.WebAssembly.

That new boundary is a known defect, [#315](https://github.com/SamG-Coder/StandardWasm/issues/315), and it predates this stage. When a method returns a `System.Type` value from a field or argument, the operand has the upstream `System.Type` class layout. The method's result type is the opaque runtime Type descriptor instead, so the `ret` check reports `-1` rather than a located diagnostic. The Stage 360 compiler and the integration line give the same result for the minimal trigger in #315. This stage only makes the method reachable.

Set STANDARDWASM_COMPILER_PATH to the compiler image and run `npm run demo -- stage-362-constrained-int32-tostring`. STANDARDWASM_MONO_CORELIB selects the browser Mono CoreLib used for linking. Without it, the runner links the installed x86 CoreCLR CoreLib.
