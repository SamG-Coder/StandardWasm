# Stage 22 · Dynamic controls

Run from the repository root after installing dependencies.

    npm run demo -- stage-22-dynamic-controls
    npm run test:winforms
    npm run bench:webgpu
    npm test

The compiler runs inside Wasm and emits Toggle from a .NET Standard DLL containing the shared control tree. One event returns 356, representing three controls and a label x coordinate of 56. The fixture also exercises capacity, duplicate keys, repeated removal and compaction of a middle record.

The Stage 14 counter adds an Add one again button on odd counts and removes it on even counts. WinForms creates and disposes an actual Button. The browser reconciles accessible hit targets by stable IDs and uploads only the changed WebGPU slots. A property-only move updates its geometry without recreating the original controls. Removing the focused button restores focus to the default button.

The native and browser checks compare captions, count, and coordinates. They drive startup, pointer activation, focused Enter, another insertion and a pointer activation of the new button. They check that the browser's removed hit region is inactive and that the original control survives. On the verified Edge run the added button changed 8,832 pixels in its WebGPU rectangle, all of which reverted after removal.

The C# collection has a declared maximum capacity. The current host supports the counter's button and label APIs and dispatches its shared click binding. General container trees, layout panels and arbitrary designer-generated WinForms applications remain open.
