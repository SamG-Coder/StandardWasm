# Upstream WinForms dependency audit

This audit backs [decision 0024](decisions/0024-binary-compatible-applications.md). It records what Microsoft's WinForms needs from Windows, so the browser platform layer can be scoped and staged.

**Upstream:** [dotnet/winforms](https://github.com/dotnet/winforms), branch `release/10.0`, commit `067fc6232013d77f7fded3c3c6797f0800ff40c4`, audited 2026-11-26.
**Installed framework compared:** Microsoft.WindowsDesktop.App 10.0.10 and Microsoft.NETCore.App 10.0.10 on Windows 11.

## Reproduce

```
git clone --depth 1 --branch release/10.0 https://github.com/dotnet/winforms.git
cd winforms
git config core.longpaths true && git restore --source=HEAD :/
cd src
S="System.Windows.Forms System.Windows.Forms.Primitives/src System.Private.Windows.Core/src System.Private.Windows.GdiPlus System.Drawing.Common/src"
# CsWin32 import lists, one name per line (functions, types and constants)
cat System.Private.Windows.Core/src/NativeMethods.txt System.Windows.Forms.Primitives/src/NativeMethods.txt \
    System.Private.Windows.GdiPlus/NativeMethods.txt System.Drawing.Common/src/NativeMethods.txt \
  | grep -vE '^\s*(//|$)' | sed 's/\s.*//' | sort -u | wc -l
# Call sites of generated interop, ranked
grep -rhoE '\bPInvoke(Core)?\.[A-Z][A-Za-z0-9]+' --include=*.cs $S | sed 's/.*\.//' | sort | uniq -c | sort -rn | head -50
# Feature usage: replace PATTERN with each regex in the table below
grep -rlE 'PATTERN' --include=*.cs $S | wc -l
```

## Platform surface

The interop is generated by [CsWin32](https://github.com/microsoft/CsWin32) from `NativeMethods.txt` lists:

| Import list | Entries (functions, types, constants) |
| --- | ---: |
| System.Windows.Forms.Primitives | 698 |
| System.Private.Windows.GdiPlus | 527 |
| System.Private.Windows.Core | 281 |
| System.Drawing.Common | 56 |
| **Unique across all four** | **1,535** |

Of these, 525 are GDI+ flat API names (`Gdip*`), and System.Drawing.Common calls 517 distinct `Gdip*` entry points.

Generated interop is called from 331 files, at 4,941 call sites covering 591 distinct API or constant groups. Direct `[DllImport]`/`[LibraryImport]` declarations are rare (22, in 15 files). The most frequent call sites are:

| Area | Most frequent call sites |
| --- | --- |
| Messages | `WM_*` 841, `SendMessage` 593, `PostMessage` 27 |
| Native common controls | `EM_*` (edit) 197, `LVM_*` (list view) 129, `TVM_*` (tree view) 70, `LB_*` 53, `TTM_*` (tooltip) 49, `CB_*` 33, `MCM_*` (month calendar) 23, `TCM_*` (tab) 20, `ImageList` 21 |
| Window management | `GetWindowLong`/`SetWindowLong` 71, `SetWindowPos` 26, `GetWindowRect` 26, `MapWindowPoints` 17, `GetFocus` 20, `InvalidateRect` 16 |
| System metrics and locale | `GetSystemMetrics` 54, `GetDeviceCaps` 50, `SystemParametersInfo` 20, `GetThreadLocale` 25 |
| GDI objects | `DeleteObject` 38, `SelectObject` 20 |
| Clipboard and drag/drop memory | `GlobalLock`/`GlobalUnlock`/`GlobalFree` 82 |
| Printing | `DMPAPER_*` 119 |
| Accessibility | `UiaDisconnectProvider` 38 |

**Finding:** standard controls are native. WinForms' TextBox, ListView, TreeView, ComboBox, ListBox, ToolTip, TabControl and MonthCalendar don't paint themselves. They create user32/comctl32 window classes and drive them with messages. Running upstream WinForms unmodified therefore means the browser layer implements those window classes and their message contracts, not just a drawing surface. Owner-drawn and fully custom-painted controls, which is how most third-party suites draw, depend mainly on GDI/GDI+ and the message loop.

## Implications for staging

1. **Runtime first.** WinForms compiles only on top of an upstream CoreLib, which needs generics, interfaces, statics, reflection metadata, unsafe code, exceptions and finalization.
2. **Message loop and window classes before drawing polish.** Every control goes through `WndProc` and `SendMessage`.
3. **GDI+ on WebGPU is a bounded, testable surface.** It has 517 entry points with deterministic outputs, which makes pixel comparison against Windows GDI+ practical.
4. **Native common controls are the largest platform cost.** Their behavior, especially editing, IME and accessibility, has to match Windows closely enough for applications that subclass them.
